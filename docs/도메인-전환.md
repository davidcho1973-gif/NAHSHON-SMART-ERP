# 도메인 붙이기

Laravel Cloud 가 준 주소(`…-tj7e94.laravel.cloud`)를 자체 도메인으로 바꾸는 절차.

**어느 배포에 붙이는지부터 정한다.** 배포마다 주소가 따로다 — 한 주소를 두 배포가
나눠 쓸 수 없다.

| 배포 | 누구 것 | 주소 |
|---|---|---|
| 운영 (`nahshon-smart-erp` · `main`) | **DASOL USA** — 우리 회사 | `erp.dasolusa.com` — **끝남** |
| 나손 (`nahshon-smart-erp` · **`nahshon-mep`**) | **NAHSHON MEP** | `erp.nahshonmep.com` — 아래 «나손에 붙일 때» 참고 |
| 스테이징 (`nahshon-smart-erp-staging` · `staging`) | KSR — 첫 시험 고객 | 나중에 KSR 주소로 |

아래는 **운영 = DASOL USA** 기준이다. 나손·KSR 에 붙일 때는 환경과 주소만 바꿔 읽으면 된다.
나손은 DNS 를 관리하는 곳이 다르므로 맨 아래 «나손에 붙일 때» 를 먼저 읽는다.

**빨리 할수록 싸다** — 전환은 데이터를 옮기는 일이 아니라 "어느 주소로 부르는가" 를
바꾸는 일이다. 나중에 할수록 다시 뽑을 종이(QR 포스터)와 다시 설치할 휴대폰만 늘어난다.

---

## 어떤 주소를 쓸 것인가

**`erp.dasolusa.com` 을 권한다.** 최상위(`dasolusa.com`)는 회사 홈페이지 자리로 비워 두는
편이 낫다. 나중에 홈페이지를 만들 때 ERP 를 다시 옮기지 않아도 된다.

고객마다 주소가 하나씩 늘어난다. `erp.<고객도메인>` 또는 `<고객>.erp.dasolusa.com` 중
하나로 정해 두면 열 번째 고객에서 규칙을 다시 만들지 않아도 된다.

바꾸고 싶으면 아래 모든 곳에서 `erp.dasolusa.com` 을 원하는 주소로 읽으면 된다.

---

## 사람이 해야 하는 일 (다섯 가지)

코드 쪽은 손댈 것이 없다. 앱 주소가 하드코딩된 곳이 한 군데도 없고 전부 `APP_URL` 에서
나온다. 아래 다섯 가지는 계정 소유자만 할 수 있다.

### 1. Laravel Cloud 에 도메인 추가

Laravel Cloud → 해당 Environment → **Domains** → `erp.dasolusa.com` 추가.
추가하면 **DNS 에 넣을 값**(CNAME 대상 또는 A 레코드 IP)을 화면에 알려 준다. 적어 둔다.

### 2. 도메인 등록업체(DNS)에 레코드 추가

`dasolusa.com` 을 산 곳(GoDaddy·Namecheap·Cloudflare 등)의 DNS 설정에서:

| Type  | Name | Value |
|-------|------|-------|
| CNAME | `erp` | *(Laravel Cloud 가 알려 준 값)* |

- 반영에 보통 **5분~1시간**, 길면 하루가 걸린다.
- Cloudflare 를 쓰면 처음에는 **회색 구름(DNS only)** 으로 두는 편이 안전하다.
  주황색(프록시)이면 인증서 발급이 막힐 수 있다. 연결이 확인된 뒤에 켜도 된다.

Laravel Cloud 가 인증서(HTTPS)를 자동으로 붙인다. **HTTPS 는 선택이 아니다** —
홈 화면 설치와 서비스워커가 HTTP 에서는 아예 동작하지 않는다.

### 3. 구글 로그인 — 두 곳을 모두

[Google Cloud Console](https://console.cloud.google.com) → API 및 서비스 → 사용자 인증 정보
→ 해당 OAuth 클라이언트 → **승인된 리디렉션 URI** 에 추가:

```
https://erp.dasolusa.com/auth/google/callback
```

**옛 주소는 지우지 말고 남겨 둔다.** 전환이 끝나고 며칠 지난 뒤에 지운다.
한쪽만 바꾸면 로그인이 통째로 막히고, 그때 되돌릴 길이 필요하다.

### 4. Laravel Cloud 환경변수 두 개

Environment → Settings → **Custom environment variables**:

```
APP_URL=https://erp.dasolusa.com
GOOGLE_REDIRECT_URI=https://erp.dasolusa.com/auth/google/callback
```

이미 있는 줄은 값만 고치고, 없으면 새 줄로 넣는다. `CACHE_STORE=file` 은 그대로 둔다.

> `SESSION_DOMAIN` 은 **넣지 않는다.** 값이 있으면 새 도메인에서 로그인 세션이 안 붙는다.

바꾼 뒤 **재배포**한다.

### 5. GitHub 변수 하나

GitHub 저장소 → Settings → Secrets and variables → Actions → **Variables** 탭.

| 어느 배포 | 어느 변수 |
|---|---|
| 운영 (DASOL USA) | `PRODUCTION_URL` |
| 스테이징 (KSR) | `STAGING_URL` |

**변수 이름을 헷갈리면 조용히 틀린다.** 운영 주소를 `STAGING_URL` 에 넣으면 배포는
성공했다고 나오는데 확인은 엉뚱한 서버를 본다. 배포가 실제로 됐는지 아무도 모르게 된다.

이걸 안 바꾸면 배포 확인과 스케줄러 점검이 계속 옛 주소를 본다.

---

## 잘 됐는지 확인하는 법

새 주소로 이걸 연다:

```
https://erp.dasolusa.com/build-version
```

세 가지를 본다.

```json
"domain": {
  "app_url": "https://erp.dasolusa.com",
  "served_from": "https://erp.dasolusa.com",
  "matches": true                      ← 이게 true 여야 한다
}
"scheduler": { "running": true }
"cache": { "store": "file" }
```

`matches` 가 **false** 면 4번(APP_URL)이 아직 반영되지 않은 것이다. 이 상태에서는
화면이 멀쩡해 보이는데 **QR·앱 설치 카드·매니페스트가 전부 옛 주소를 가리킨다.**
배포할 때마다 GitHub Actions 요약에도 경고로 뜬다.

그다음 **로그인을 한 번 해 본다.** 이게 3번이 제대로 됐는지 확인하는 유일한 방법이다.

## 전환 뒤에 해야 하는 것

주소가 바뀌면 따라오지 않는 것들이 있다. 브라우저가 도메인마다 따로 관리하기 때문이다.

| 무엇 | 왜 | 할 일 |
|---|---|---|
| **현장 QR 포스터** | 종이에 옛 주소가 인쇄돼 있다 | 다시 뽑아 붙인다 |
| **홈 화면 아이콘** | 매니페스트를 다시 읽지 않는다 | 지우고 다시 추가 |
| **"이 휴대폰 기억"** | localStorage 는 도메인마다 따로다 | 작업자가 한 번 이름 다시 선택 |
| **W-9 작성 링크** | 서명이 주소에 묶여 있다 | 다시 보낸다 |

데이터는 하나도 안 없어진다. 사람이 한 번씩 다시 하는 것뿐이다.
**그래서 현장이 쉬는 날에 하는 편이 좋다.**

**아직 아무도 안 쓰는 새 배포라면 이 표는 통째로 해당 없다.** 붙일 종이도, 설치된
휴대폰도 없기 때문이다. 도메인을 먼저 붙이고 시작하는 것이 가장 싸다.

---

## 순서 요약

1. Laravel Cloud 에 도메인 추가 → DNS 값 확인
2. 등록업체에 CNAME 추가 → 연결될 때까지 대기
3. 구글 콘솔에 리디렉션 URI 추가
4. `APP_URL` · `GOOGLE_REDIRECT_URI` 변경 → 재배포
5. `/build-version` 에서 `matches: true` 확인 → 로그인 테스트
6. GitHub `PRODUCTION_URL` (스테이징이면 `STAGING_URL`) 변경
7. QR 포스터 다시 인쇄, 작업자 아이콘 재설치 안내

## 나손에 붙일 때 — `erp.nahshonmep.com` (David 지시 2026-09-03)

> "이 주소를 nahshonmep.com 홈페이지 주소로 만들고 싶어. erp.nahshonmep.com 주소로 만들어줘"

위 절차 그대로인데 **세 가지가 다르다.** 여기서 틀리면 나손이 아니라 DASOL 원본에
도메인이 붙거나, 회사 메일이 멈춘다.

### 다른 것 1 — 환경이 `main` 이 아니라 `nahshon-mep` 이다

Laravel Cloud → `nahshon-smart-erp` → 파란 네모가 **`NAHSHON MEP`** 인 환경 → Domains.
같은 앱 안에 `main`(DASOL) 환경이 함께 있다. `main` 의 Domains 에 넣으면 나손 주소로
DASOL 데이터베이스가 열린다. 환경변수(`APP_URL`, `GOOGLE_REDIRECT_URI`)도 같은 환경에 넣는다.

### 다른 것 2 — DNS 는 Netlify 에 있다 (GoDaddy 가 아니다)

`nahshonmep.com` 의 네임서버는 `dns1~4.p03.nsone.net` 이고 관리자는 Netlify 다
(회사 홈페이지가 거기 있다 — `MAIL_SETUP.md` 에 확인 기록). 그러니 레코드는
**Netlify → Domains → nahshonmep.com → DNS settings** 에 넣는다. GoDaddy 화면에서
넣으면 저장은 되는데 아무 효과가 없다.

| Type | Name | Value | TTL |
|---|---|---|---|
| A (또는 CNAME) | `erp` | *(Laravel Cloud Domains 화면이 알려 준 값)* | 300 |

- **Name 칸에는 `erp` 만.** 전체 주소를 넣으면 `erp.nahshonmep.com.nahshonmep.com` 이 된다.
- Laravel Cloud 가 IP 를 주면 A, 호스트 이름을 주면 CNAME. 둘 중 화면에 나온 것을 쓴다.
- Laravel Cloud 의 토글 세 개(wildcard / Cloudflare / uninterrupted transfer)는 **전부 끈다.**
- `erp` 서브도메인은 지금 비어 있어서 (`MAIL_SETUP.md`) 다른 것과 부딪히지 않는다.

**루트 도메인의 것은 하나도 건드리지 않는다.** 회사 메일이 멈춘다.

- MX (`nahshonmep-com.mail.protection.outlook.com`)
- SPF TXT (`v=spf1 include:spf.protection.outlook.com -all`)
- `selector1/2._domainkey` DKIM CNAME, `autodiscover` CNAME
- 홈페이지가 보는 `@` / `www` 레코드

`erp` 한 줄만 **추가**한다. 기존 줄을 고치거나 지우는 일은 없다.

### 다른 것 3 — GitHub 변수는 바꿀 것이 없다

나손 환경은 GitHub Actions 배포 잡이 없다(`PRODUCTION_URL` 은 DASOL, `STAGING_URL` 은 KSR).
대신 **Actions → «Check production» 워크플로**가 `erp.nahshonmep.com/build-version` 도
함께 읽으므로, 도메인이 붙었는지는 그 버튼 한 번으로 확인할 수 있다.

### 나손 기준 값

```
도메인:              erp.nahshonmep.com
리디렉션 URI:        https://erp.nahshonmep.com/auth/google/callback
APP_URL:             https://erp.nahshonmep.com
GOOGLE_REDIRECT_URI: https://erp.nahshonmep.com/auth/google/callback
확인 주소:           https://erp.nahshonmep.com/build-version   ← domain.matches: true
```

구글 콘솔에서 고칠 OAuth 클라이언트는 **나손 환경의 `GOOGLE_CLIENT_ID` 와 같은 것**이다.
클라이언트가 여럿이라 엉뚱한 것에 URI 를 넣으면 `redirect_uri_mismatch` 가 난다.
옛 laravel.cloud 주소의 URI 는 며칠 지난 뒤에 지운다.

### 전환 뒤

옛 주소 `https://nahshon-smart-erp-nahshon-mep-hntasf.laravel.cloud` 는 계속 열린다 —
Laravel Cloud 가 기본 주소를 없애지 않는다. 다만 `APP_URL` 이 새 주소로 바뀐 뒤에는
옛 주소로 연 화면의 QR·설치 카드가 새 주소를 가리키므로, 사람들에게는 새 주소만 알린다.
휴대폰에 홈 화면 아이콘을 이미 만든 사람은 지우고 새 주소로 다시 추가한다.
