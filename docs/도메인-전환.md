# 도메인 전환 — DASOLUSA.COM

앱을 `nahshon-smart-erp-staging-main-tj7e94.laravel.cloud` 에서 자체 도메인으로 옮기는 절차.

**지금이 좋은 시점인 이유** — 쌓인 데이터가 거의 없다. 전환은 데이터를 옮기는 일이 아니라
"어느 주소로 부르는가" 를 바꾸는 일이라, 나중에 할수록 다시 뽑을 종이(QR 포스터)와
다시 설치할 휴대폰만 늘어난다.

---

## 어떤 주소를 쓸 것인가

**`erp.dasolusa.com` 을 권한다.** 최상위(`dasolusa.com`)는 회사 홈페이지 자리로 비워 두는
편이 낫다. 나중에 홈페이지를 만들 때 ERP 를 다시 옮기지 않아도 된다.

바꾸고 싶으면 아래 모든 곳에서 `erp.dasolusa.com` 을 원하는 주소로 읽으면 된다.

---

## 사람이 해야 하는 일 (다섯 가지)

코드 쪽은 손댈 것이 없다. 앱 주소가 하드코딩된 곳이 한 군데도 없고 전부 `APP_URL` 에서
나온다. 아래 다섯 가지는 계정 소유자만 할 수 있다.

### 1. Laravel Cloud 에 도메인 추가

Laravel Cloud → 해당 Environment → **Domains** → `erp.dasolusa.com` 추가.
추가하면 **DNS 에 넣을 값**(CNAME 대상 또는 A 레코드 IP)을 화면에 알려 준다. 적어 둔다.

### 2. 도메인 등록업체(DNS)에 레코드 추가

`dasolusa.com` 을 산 곳(GoDaddy·Namecheap·Cloudflare 등)의 DNS 설정에서:

| Type  | Name | Value |
|-------|------|-------|
| CNAME | `erp` | *(Laravel Cloud 가 알려 준 값)* |

- 반영에 보통 **5분~1시간**, 길면 하루가 걸린다.
- Cloudflare 를 쓰면 처음에는 **회색 구름(DNS only)** 으로 두는 편이 안전하다.
  주황색(프록시)이면 인증서 발급이 막힐 수 있다. 연결이 확인된 뒤에 켜도 된다.

Laravel Cloud 가 인증서(HTTPS)를 자동으로 붙인다. **HTTPS 는 선택이 아니다** —
홈 화면 설치와 서비스워커가 HTTP 에서는 아예 동작하지 않는다.

### 3. 구글 로그인 — 두 곳을 모두

[Google Cloud Console](https://console.cloud.google.com) → API 및 서비스 → 사용자 인증 정보
→ 해당 OAuth 클라이언트 → **승인된 리디렉션 URI** 에 추가:

```
https://erp.dasolusa.com/auth/google/callback
```

**옛 주소는 지우지 말고 남겨 둔다.** 전환이 끝나고 며칠 지난 뒤에 지운다.
한쪽만 바꾸면 로그인이 통째로 막히고, 그때 되돌릴 길이 필요하다.

### 4. Laravel Cloud 환경변수 두 개

Environment → Settings → **Custom environment variables**:

```
APP_URL=https://erp.dasolusa.com
GOOGLE_REDIRECT_URI=https://erp.dasolusa.com/auth/google/callback
```

이미 있는 줄은 값만 고치고, 없으면 새 줄로 넣는다. `CACHE_STORE=file` 은 그대로 둔다.

> `SESSION_DOMAIN` 은 **넣지 않는다.** 값이 있으면 새 도메인에서 로그인 세션이 안 붙는다.

바꾼 뒤 **재배포**한다.

### 5. GitHub 변수 하나

GitHub 저장소 → Settings → Secrets and variables → Actions → **Variables** →
`STAGING_URL` 을 `https://erp.dasolusa.com` 으로.

이걸 안 바꾸면 배포 확인과 스케줄러 점검이 계속 옛 주소를 본다.

---

## 잘 됐는지 확인하는 법

새 주소로 이걸 연다:

```
https://erp.dasolusa.com/build-version
```

세 가지를 본다.

```json
"domain": {
  "app_url": "https://erp.dasolusa.com",
  "served_from": "https://erp.dasolusa.com",
  "matches": true                      ← 이게 true 여야 한다
}
"scheduler": { "running": true }
"cache": { "store": "file" }
```

`matches` 가 **false** 면 4번(APP_URL)이 아직 반영되지 않은 것이다. 이 상태에서는
화면이 멀쩡해 보이는데 **QR·앱 설치 카드·매니페스트가 전부 옛 주소를 가리킨다.**
배포할 때마다 GitHub Actions 요약에도 경고로 뜬다.

그다음 **로그인을 한 번 해 본다.** 이게 3번이 제대로 됐는지 확인하는 유일한 방법이다.

---

## 전환 뒤에 해야 하는 것

주소가 바뀌면 따라오지 않는 것들이 있다. 브라우저가 도메인마다 따로 관리하기 때문이다.

| 무엇 | 왜 | 할 일 |
|---|---|---|
| **현장 QR 포스터** | 종이에 옛 주소가 인쇄돼 있다 | 다시 뽑아 붙인다 |
| **홈 화면 아이콘** | 매니페스트를 다시 읽지 않는다 | 지우고 다시 추가 |
| **"이 휴대폰 기억"** | localStorage 는 도메인마다 따로다 | 작업자가 한 번 이름 다시 선택 |
| **W-9 작성 링크** | 서명이 주소에 묶여 있다 | 다시 보낸다 |

데이터는 하나도 안 없어진다. 사람이 한 번씩 다시 하는 것뿐이다.
**그래서 현장이 쉬는 날에 하는 편이 좋다.**

## 순서 요약

1. Laravel Cloud 에 도메인 추가 → DNS 값 확인
2. 등록업체에 CNAME 추가 → 연결될 때까지 대기
3. 구글 콘솔에 리디렉션 URI 추가
4. `APP_URL` · `GOOGLE_REDIRECT_URI` 변경 → 재배포
5. `/build-version` 에서 `matches: true` 확인 → 로그인 테스트
6. GitHub `STAGING_URL` 변경
7. QR 포스터 다시 인쇄, 작업자 아이콘 재설치 안내
