# 기성 통합 편집 구현 기준

2026-10-18 사용자 승인 범위. 완료 체크는 구현·검증한 경우에만 한다.

## 원인과 기준

현재 원장·도면 표시·원청 엑셀·제출 패키지가 각각 존재하지만 입력과 검토 화면이 분리되어 있다. 별도 기성 원장을 추가하지 않고 ClaimEvidenceService와 기존 제출 검증을 단일 기준으로 사용한다.

설치가 반입 증빙을 대신하는 기본 동작은 제거한다. 도면상 물량과 실제 시공량을 분리하며 AI 결과는 확인 전 초안이다. 기존 제출본과 원본 파일은 보존한다.

## 완료 조건

- [ ] 계약/현장별 청구 가능액, 회차별 배정액, 미확인량, 구체적 누락 근거와 다음 행동
- [ ] 작업일·위치·수량·기존 증빙을 한 화면에서 기록
- [ ] 반입 자동 생성 제거 및 명시적 반입 수량·근거 검증
- [ ] 큰 도면과 산출표 연결, 축척 검증, 개구부 공제
- [ ] 표시 이동·크기·복사·삭제·실행 취소·다시 실행
- [ ] 사진 순서·회전·설명과 제출용 편집본
- [ ] 초안 자동 저장·수정 이력·충돌 방지·일괄 수정
- [ ] 도면 선택 영역 AI 질문, 근거와 변경 미리보기, 선택 적용·되돌리기
- [ ] 기존 증빙 접근권한 재검사 및 미확인 AI 결과 청구 차단
- [ ] 기성 엑셀·산출표·표시 도면·사진대지·증빙 목차·원본 제출 묶음
- [ ] 관련 테스트, 전체 회귀, Chromium, staging, main, NAHSHON 실제 배포 확인

## 연계 지점

- `ClaimEvidenceService`: 실제/예상/원문 기록, 확인, 회차 배정
- `DrawingMarkService` / `drawing-marker.js`: 도면 원본과 별도 표시
- `ClaimSubmissionService`: 계약별 필수자료·해시 검증·불변 제출본
- `GcClaimWorkbookService`: 지원되는 원청 양식
- `admin-section-drawings.js`: 공정별 진입점

새 기능은 이 흐름에 연결한다. 지원되지 않는 원청 양식이나 불명확한 축척은 성공으로 간주하지 않는다.
