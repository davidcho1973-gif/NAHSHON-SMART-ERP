# 직원 이메일 로그인

원인: 활성 로그인 계정을 가지고 있어도 Google 계정이 없으면 공개 로그인 화면에서 시작할 수 없었다. 일반 비밀번호 링크는 삭제된 `/admin/login`을 가리켰다.

## 직원 안내

1. `/login`에서 **등록 이메일**과 **비밀번호**를 입력한다. Gmail, Outlook, Yahoo, 회사 이메일 등 모두 사용할 수 있다.
2. 아직 Google/PIN/이메일 비밀번호를 설정하지 않은 활성 직원 계정은 등록된 전화번호 끝 **4자리**로 시작한다. 앞의 `0`도 입력한다.
3. 최초 확인 후 **5분 이내** 영문과 숫자를 포함한 **8자 이상** 비밀번호를 정한다. 이 설정 전에는 ERP 로그인 권한이 생기지 않는다.
4. 다음 접속부터 이메일과 새 비밀번호를 사용한다. 전화번호 끝 4자리는 재사용할 수 없다.
5. 기존 Google 또는 PIN 사용자는 기존 방식으로 로그인한 뒤 ERP 프로필 메뉴 또는 작업자 앱 **나 → 이메일 비밀번호 설정**에서 추가한다. 기존 이메일 비밀번호를 바꿀 때는 현재 비밀번호를 입력해야 한다.

## 관리자 확인

- 직원 등록(Employee)과 로그인 계정(User)은 별도다. 인원관리에서 직원의 로그인 계정을 생성·활성화하고 역할과 범위를 확인한다. 공개 로그인은 계정 생성이나 권한 승격을 하지 않는다.
- 최초 전화번호 확인에는 계정과 직원의 이메일이 같아야 하며 유효한 등록 전화번호가 있어야 한다. 계정은 활성, 직원은 재직(active) 상태여야 한다.
- 실패 안내는 존재 여부를 구분하지 않는다. 한 계정의 5회 실패는 15분 잠금이며 IP를 바꿔도 유지된다. 별도 IP 제한은 분당 10회다.
- 실제 전화번호 끝자리 또는 비밀번호를 안내문·감사 로그에 기록하지 않는다. 사용자가 직접 입력한다.
- 기존 Google/PIN 계정에는 전화번호 우회 로그인을 열지 않는다. 비밀번호 설정은 이메일 소유권 인증이 아니므로 `email_verified_at`을 변경하지 않는다.
- 비밀번호를 잊었다고 전화번호 끝 4자리로 자동 초기화하지 않는다. Google/PIN 등 사용 가능한 기존 인증과 관리자 지원으로 별도 처리해야 한다.

## 배포

추가 migration은 `users`에 비밀번호 설정 시각과 실패·잠금 필드를 추가한다. 기존 해시/권한/직원 연락처는 변경하지 않는다. 기존 무작위 자리값 password는 이메일 인증에 허용하지 않는다. 환경변수 또는 메일/SMS 업체 설정은 필요 없다. Google/PIN 기능을 유지한다.

검증: 별도 PostgreSQL 테스트 DB에서 최초 설정, 숫자 선행 0, 일반 이메일, 역할 유지, Google/PIN 우회 차단, 재직/계정 상태, 반복 실패, 설정 만료·재사용·연락처 변경, 비밀번호 변경 및 화면을 검사한다. 운영 직원 계정으로 로그인하거나 비밀번호를 변경하는 검증은 하지 않는다.
