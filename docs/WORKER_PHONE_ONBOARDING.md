# 이름·전화번호로 작업자 앱 연결

## 사용 순서

1. ERP 직원 등록·관리에서 **작업자 간편등록 · 가입 QR · 승인 · 앱 연결**을 연다. 반장은 출퇴근 앱 첫 화면의 **작업자 가입 승인**에서 들어간다. 직접 주소는 `/worker-onboarding`.
2. 승인할 팀의 **가입 QR**을 발급한다. 회사·현장·팀은 QR에 지정되어 작업자가 고를 필요가 없다. 가입 QR은 7일 유효하며 신청용이지 로그인 열쇠가 아니다.
3. 작업자는 이름과 전화번호만 제출한다. 미국 번호는 10자리, 다른 국가 번호는 +국가번호를 포함한다. 이메일이나 SMS 발송 서비스가 필요 없다. 신청 직후는 승인 대기이며 직원·로그인 계정은 아직 생성되지 않는다.
4. 관리자 또는 배정된 반장이 본인과 팀을 확인했다는 체크 후 승인한다. 신규 직원은 시급 작업자(`direct`, `worker`, `self`)로 기존 직원 명단에 연결된다. 이 승인은 출퇴근 계정 승인으로, 안전교육·세무서류 완료를 의미하지 않는다.
5. **개인용 앱 연결 QR**을 발급하여 본인 휴대폰으로 스캔하게 한다. 원격이면 본인 확인 후 링크를 개인적으로 전달한다. 15분 유효·한 번 사용, 재발급 시 이전 미사용 링크는 무효다. 외부 QR 생성 사이트로 개인 토큰을 전송하지 않는다.
6. 직원이 기존 PIN 화면에서 4자리 PIN을 직접 설정하면 출퇴근 앱으로 로그인된다. 반복 숫자·연속 숫자·전화번호 끝 4자리는 거절한다. 기기 토큰과 PIN을 함께 사용한다. 관리자에게 PIN은 보이지 않는다.
7. 다음부터 로그인 상태를 유지한다. 로그아웃 시 기억된 기기에서 PIN 로그인. 기기 교체/분실은 기존 직원 관리의 PIN 재설정 절차를 사용한다. 새 가입 요청으로 이미 활성화된 사람의 기기를 재연결하지 않는다.

앱 연결용 개인 QR과 매일 출퇴근용 현장 QR은 다르다. 기존 출퇴근 앱의 현장 QR 및 위치 판정 규칙은 그대로 유지한다. 가입 승인만으로 출근 기록이 자동 생성되지는 않는다.

## 권한과 데이터

- 전체 관리자: 팀 전체. 인사·현장소장: 승인된 범위. 반장: 사용자 팀 범위, 직원 팀·회사·현장, 실제 팀 반장 배정이 모두 일치하는 자기 팀만.
- 일반 작업자는 승인 화면과 발급 API에 접근하지 못한다. 제출한 역할·상태 값은 무시한다.
- 기존 번호가 같은 팀의 활성 시급 작업자이고 이름도 같으면 기존 Employee에 연결하여 사번·출퇴근 이력을 보존한다. 다른 팀·다른 이름·중복 번호·관리 계정·기존 PIN 계정은 자동 연결하지 않고 관리자 확인을 요구한다.
- 공개 재제출로 이름/소속/승인 상태를 덮어쓰지 않는다. 승인된 신규 흐름의 직원은 과거 공개 재등록 경로로 소속 변경하지 못한다.
- 신청은 `worker_enrollments`, 승인된 직원과 로그인은 기존 `employees/users`, PIN은 기존 `auth_setup_tokens/login_devices`, 실제 출퇴근은 기존 출퇴근 앱을 사용한다.
- `users.email`은 nullable로 변경한다. 작업자/반장의 이메일 없는 계정 수정도 기존 관리 화면에서 지원한다. 관리자 계정에는 이메일이 필요하다.
- 승인 후 시급 금액을 급여 설정에서 입력/확인해야 한다. 이 기능이 임금률을 추정하지 않는다.

## 운영 범위

기존 공용 가입 QR은 관리자·협력사 등의 기존 등록을 위해 유지한다. 시급 작업자에게는 이 화면에서 발급한 **팀 가입 QR**을 배포한다. 팀이 없거나 반장 계정과 팀 배정이 일치하지 않으면 관리자가 기존 팀 설정에서 먼저 정리한다.

기존 직원 데이터 일괄 변환이나 가짜 이메일 생성은 하지 않는다. 반려된 신청의 재처리 및 소속 변경은 인사담당자의 기존 직원 관리로 처리한다. 직원 명단을 삭제하지 않고 정지/퇴사 상태로 관리한다.

## 검증

`WorkerEnrollmentTest`에서 실제 HTTP 등록→승인→QR→PIN→출퇴근 앱, 이메일 없는 계정 수정, 기기 PIN 재로그인, 범위 위반, 변조/만료 링크, 중복 번호, 기존 사번 유지, 약한 PIN, 중지/승격 계정 차단을 검증한다. 운영 직원 계정으로 시험하지 않는다.
