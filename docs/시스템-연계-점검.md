# 전체 시스템 연계 점검 — 돈·사람·정보의 흐름

2026-08-23. David 지시: "시행 전 전체 프로그램을 다시 살펴봐 — 모든 과정이 연계되고
소통하고 연동되어야 해." 세 갈래(돈/사람/정보·알림)로 코드를 전수 추적한 결과다.
각 항목에 파일 경로가 있으므로 수선 시 이 문서가 작업 지시서다.

## 총평

뼈대는 건강하다 — 커넥터 4종의 멱등 규약이 완전히 일치하고, 승인·기성·접수의 정본이
한 곳씩 있으며, 등록→직원→계정→급여프로필이 자동으로 이어진다. 끊긴 곳은 세 무늬로
요약된다:

1. **기록은 되는데 아무도 안 읽는 데이터** — 원가 귀속(project_id·wbs_code), 서명
   employee_id, flow=in 돈 문서, W-9, PayApplication.source_ref.
2. **정본이 여럿인데 대조 장치가 없는 데이터** — 경비 5개 입구, 만료일 3원장,
   인원 3원장, 기성 산식 재구현.
3. **결정이 사람에게 되돌아오지 않는 흐름** — 승인/반려·입고·기성 확정이 방(K-TALK)
   으로 안 돌아오고, 재무·조달은 통합 알림에 한 줄도 안 넣는다.

## 즉시 수선함 (이 점검에서 바로 고친 3건)

1. **공개 QR 등록이 기존 계정을 재바인딩하던 문** — 남의 이메일을 적으면 그 계정의
   직원 연결·이름이 바뀌었다. 이미 다른 직원에 연결된 계정이면 건너뛰고 보고만 한다.
   (`MemberRegistration::syncAccessUser`)
2. **작업자앱 출퇴근에 재직 검사 없음** — 게이트·QR 은 막는데 이 길만 열려 있었다.
   (`WorkerAttendanceService::punch`)
3. **⚠️ 충돌 경고가 폰을 안 울림** — 상황실 AI 답글만 ChatPushNotifier 를 우회했다.
   (`OpsRoomAutoReader::reply`)
4. (보너스) **정식 등록 경로의 employment_type·preferred_language 누락** — 협력사
   인원이 시급 직영으로 둔갑하던 구멍. (`MemberRegistration::syncEmployeeRecord`)

## 3. 정보·알림의 흐름

**문서**: 두 체계(문서관리=편철 원장 / AI문서함=판독 엔진)는 의도된 분업이지만 —
같은 파일을 AI 가 2~3번 읽고(문서관리 업로드가 두 분석 잡을 모두 발화), 어휘(25종
vs 29종)가 안 맞는 채 다리가 그대로 복사하고, integrated 출신은 판독 결과를 못
돌려받고, 삭제가 전파되지 않으며, dwg/dxf 는 다리가 조용히 건너뛴다. 계약서→계약
모듈(project_contract_id) 자동 링크 없음. 납품서 판독 규칙이 두 벌(조달 화면 전용
vs 문서함).

**알림**: 6갈래·받은편지함 2개·발원점 5곳. UnifiedAlertService::emit 설계는 훌륭한데
호출자가 문서 모듈뿐 — 재무(FIN)·조달(PROC)·출근(ATT)은 0건. 같은 계약 증빙 만료가
서로 다른 임계값으로 3번 감. 다이제스트는 방+종 2번. 알림 소유자 판정이 employee_id/
user_id 중 한 칸만 봄(orWhere 필요). **어느 갈래에도 안 실리는 사건**: 기성 75일
미수, 과청구, 조달 ETA 초과, 승인 대기 적체, 결근, 문서 원본 유실.

**되돌아오는 길**: 경비 승인/반려(방 답글은 영원히 "승인대기"), 공정 반영(apply),
조달 입고("그거 언제 와요"의 답), 기성 확정·수금 — 전부 방으로 안 돌아옴. 같은
파일을 두 방에 올리면 답글이 첫 방에만 감(멱등 키가 document_id 뿐).

**대시보드**: financeStats 가 기성 산식 재구현(위임 필요), 현장 스코프 규칙이 두
화면에서 다름(site NULL 이 전 현장에 중복 계상), todayInspections 상수 0,
rentalStats 에 소유 장비 혼입, 지휘본부 진행률 가중치가 정본과 다름,
toolStats·ptwList 는 하드코딩 가짜 데이터(가짜 숫자는 빈 것보다 나쁘다).
