# 공정관리 차세대 기획 — 진단과 설계

2026-08-23. David 질문: "현재 공정관리가 세계 최고 수준인가? 다른 건설사는 어떻게
하나? AI 로 여러 명 몫을 혼자, 화면은 누구나 한눈에." 코드 전수 진단 2건 + 업계
벤치마크 2건(웹 조사, 출처 표기)을 종합한 기획이다. **개발 전 기획 단계** — 실행은
사장 승인 후.

---

## 1. 정직한 진단 — 우리는 지금 어디인가

### 이미 상용 도구 수준을 넘는 것

- **입력 파이프라인**: K-TALK 현장 상황실 방에 글이 올라오면 AI 가 버튼 없이 자동
  판독 → 공정/조달/인력/지출 분류 → 확인 후 반영(OpsRoomAutoReader + OpsIntakeService,
  환각 차단·되돌리기·학습 루프 포함). Procore 가 2025~26년에야 내놓은 Schedule
  Agent 와 같은 지점을 우리는 이미 돌리고 있다. ("카톡 붙여넣기" 화면은 K-TALK
  이전의 구형 입구 — 외부 카톡 대화용으로만 남기고 일상 경로에서 뺀다, David
  확인 2026-08-23.)
- **공정표 생성**: PDF/XLSX 공정표를 AI 가 전량 추출(CpmExtraction — 요약 금지 사양,
  두 엔진 교차). 문서→WBS 트리가 자동이다.
- **공정↔안전↔인력**: 안전카드(wbs_code)→서명(employee)→타임시트 사슬. TBM 게이트
  ("안전 없이 공정 없다")를 서버가 강제. 사진→진행률 AI 추천도 안전카드 경로에 있다.
- **공정↔조달↔원가**: need-by(공정 종료일) 대비 ETA 슬랙, 입고완료→경비 자동 계상.

### 세 개의 큰 구멍 (수작업이 몰려 있는 곳)

1. **CPM 계산 엔진이 없다.** preds·float_days·is_critical 은 외부 엑셀 값을
   저장·표시할 뿐, 재계산 로직이 코드베이스에 전무하다. 선행 작업이 밀려도 후속
   영향과 준공일 변화를 시스템이 모른다 — 주공정 판단의 정본이 여전히 외부 엑셀
   작성자다.
2. **공정→기성 청구가 완전히 끊겨 있다.** 액티비티별 planned_cost 와 진척률이 DB 에
   있는데도 기성(Σ planned_cost × progress)이 자동 산출되지 않아 G702/G703 라인
   배분을 사장이 손으로 계산한다. 시간이 가장 많이 들고 오류가 가장 비싼 수작업.
3. **화면이 6층으로 쌓여 있고 진행률 입력 입구가 4곳이다.** KPI 7장 + 2탭 + 토글 +
   9열 트리; 행 버튼/편집 모달/작업안전 마감/상황실 판독이 서로 다른 메뉴에 흩어져
   "어디서 입력하는 게 정답인지"가 불명확. WBS·CPM·MH·ES/EF·영문 공종코드가 번역
   없이 노출. (버그: 사이드바 라우트 타이틀 mojibake — 'ê³µì •…')

**답: 세계 최고는 아니다. 그러나 방향은 세계 최전선과 같다** — ALICE·Procore·Trunk
Tools 가 지금 공략하는 지점(입력 파싱→기준 대비 비교→편차 경고)을 우리는 자체
파이프라인으로 이미 절반 왔고, 그들이 못 하는 "대화로 갱신까지"는 우리가 앞서 있다.
빠진 것은 **계산 엔진(CPM·기성)** 과 **화면의 단순함**이다.

## 2. 다른 회사들은 어떻게 하나 (벤치마크 요지)

**3층 구조다:**

| 층 | 누가 | 무엇으로 |
|---|---|---|
| 계약·기준공정표 | 대형사/발주처 요구 | Primavera P6 + **전담 스케줄러** (중소사는 외주) |
| 현장 실행 | 규모 무관 사실상 표준 | **주간 리듬**: 3주 선행계획 + 주간 약속 + PPC + 제약 제거 (Last Planner System) |
| 중소 전문건설사 현실 | 우리 규모 | **엑셀·화이트보드·문자** (설문 40%+ 가 PM 을 스프레드시트로) |

핵심 통찰 셋:

- **"우리의 경쟁 상대는 Procore 가 아니라 엑셀이다."** 입력은 엑셀보다 쉬워야 하고
  (사진·붙여넣기·음성→AI), 대신 엑셀이 못 하는 의존관계 자동 재계산을 준다.
- **도구보다 리듬.** P6 회사든 엑셀 회사든 실제로 작동하는 것은 "매주 같은 요일의
  갱신 사이클"이다. "안 갱신된 선행계획은 없느니만 못하다."
- **AI 도구 시장은 양분.** ALICE($50~150K/년)·nPlan·Buildots(연매출 $250M+ GC 대상)는
  우리 규모가 살 물건이 아니다. 살 만한 것은 OpenSpace(~$10K/년)·SmartPM 정도.
  그들의 핵심 아이디어를 자체 구현하는 것이 구매보다 현실적이다 — 그리고 그 재료
  (AI 파이프라인, CPM 필드, 사진, 채팅)를 우리는 이미 갖고 있다.
- **플랜트 설비 업종 특화**: EPC 계열은 진척을 감이 아니라 **rules of credit**
  (스풀 기준 자재입고 10%/가설치 40%/용접 30%/검사 20% 식 가중치)로 측정한다.
  배관은 스풀/용접점 단위 수량화가 잘 되는 업종이라 우리에게 정확히 맞는다.
- 지연 원인 통계: 인력 부족(45%), 자재/공급망(65%), 설계변경이 3대 축. 사유를
  표준 코드로 쌓아야 "우리 회사 지연 원인 1위"를 데이터로 안다(LCI Reasons for
  Variance 표준 목록 존재).

## 3. 설계 — 다섯 기둥

원칙: **측정은 규칙이, 계산은 엔진이, 해석은 AI 가, 확정은 사람이.** 화면은 한 장.

### P1. 사내 CPM 엔진 (가장 레버리지 큰 한 수) — 크기: 중

preds·days·planned_start 가 이미 컬럼에 있다. forward/backward pass 서비스 하나면:
일정 편집·상황실 반영·조달 ETA 지연이 **즉시 후속 공정과 준공일에 전파**되고,
"자재 5일 지연 → 준공 D+3일" 같은 구체 수치가 나오며, 외부 엑셀 재작성 의존이
끊긴다. 오늘 할 일의 임계경로 정렬도 항상 최신이 된다.

### P2. 주간 리듬 자동화 (LPS 이식) — 크기: 중

- 매주 월: 지난주 실적 자동 집계 → **3주 선행 뷰** 자동 생성 (사장은 검토만)
- "이번 주 약속" 플래그 → 주말 **PPC(약속 이행률)** 자동 계산
- 미완료 사유를 **표준 코드**(인력/자재/선행작업/변경지시/날씨/검사대기 — LCI 표준)
  드롭다운으로: AI 가 "이번 주 PPC 72%, 미완료 4건이 자재 지연 — PO #123 원인"
- 작업 시작 가능(ready) 판정: 자재 PO 상태·선행작업·TBM 을 작업 레코드에 묶어
  시스템이 판정 — **제약 제거가 관리의 본질**
- 진척 측정에 **rules of credit** 도입(배관: 스풀·용접점 가중치) — 반장의 수량
  보고만으로 진척·기성 근거·지연 여부가 자동 산출

### P3. 돈 연결 완성 — 크기: 중

- **기성 자동 초안**: Σ(planned_cost × effectiveProgress) → PayApplication draft.
  청구 준비가 "계산"에서 "검토"로 준다. (BillingCalculator 산식은 이미 견고)
- **공정별 노무원가**: WbsLaborService 실인시 × 급여 단가 → planned_cost 대비
  실적 원가가 자재+노무로 완성
- 인원 3원장(상황실 보고/안전카드 서명/QR 출퇴근) 자동 대조를 일일 마감에 추가

### P4. AI 도우미의 공정 완성 (스마트 ④·⑤ 와 합류)

- "@AI A작업 3일 밀리면 뭐가 밀려?" → P1 엔진 위에서 tool use 로 답하고, 확인
  버튼 한 번으로 갱신까지 (상용 제품은 조회까지만 — 갱신형은 우리가 앞선다).
  답변에 근거 액티비티 링크 필수(Trunk Tools 방식, 87% 정확도 검증 사례).
- 사진→진행률 반자동(WbsPhoto + Vision → 제안 → 승인): Buildots 경량판.
  360° 카메라·BIM 없이 스풀/구간 단위 배관에는 충분.
- 자사 이력 지연 위험 점수: 완료 프로젝트의 계획 대비 실적 배율 통계 → 새 공정표
  등록 시 위험 액티비티 경고 배지 (nPlan 축소판).
- 아침 다이제스트에 "오늘 가장 위험한 3가지"를 영향도 순으로 (스마트 ① 과 합류).

### P5. 화면 한 장 원칙 — 크기: 소~중

- 위에서부터: **① 오늘 할 일(다음 행동 버튼) ② 간트 ③ KPI 3장**(전체 진척·임계
  완료/전체·오늘 TBM 대기). 나머지는 접기/이동.
- 트리 9열 → **5열**(상태·작업명·담당·기간·진척). MH·ID·선행 수는 편집 모달로.
- **진행률 입력 입구 단일화**: 상태 버튼 + AI 확정만. 편집 모달의 % 직접 입력은
  고급 접기. 보고의 정본은 **K-TALK 상황실 방(자동 판독)** — 관리 화면의 "카톡
  붙여넣기" 패널은 접거나 제거(외부 카톡 대화 전용 보조로만).
- 용어 한글화: 공종 영문코드 → 전기/배관/기계…, 상태 5종 → 사용자에겐 3종
  (대기/진행/완료), 임계경로·여유는 툴팁이 아니라 본문 한 줄로.
- 모바일: '오늘 할 일 + 입력창'만 남기는 축약 뷰 (todayWork 데이터 재사용, 비용 낮음).
- 버그: 라우트 타이틀 mojibake 일괄 수정.

## 4. 권장 순서

| 단계 | 내용 | 이유 |
|---|---|---|
| 1 | **P5 화면 한 장** + mojibake 수정 | 즉시 체감, 위험 없음 |
| 2 | **P1 CPM 엔진** | 나머지 전부의 기반 (지연 전파·위험 3가지·what-if) |
| 3 | **P3 기성 초안** | 사장 시간을 가장 많이 돌려주는 것 |
| 4 | **P2 주간 리듬** (약속·PPC·사유 코드·rules of credit) | 데이터가 쌓여야 P4 위험 점수가 산다 |
| 5 | **P4 대화형·사진·위험 점수** (스마트 ④·⑤ 합류) | 엔진+데이터 위에서 완성 |
