# 구매신청 / 구매 처리

수퍼관리자가 계정·권한에서 관리자별 **구매신청**, **구매처리**를 각각 지정한다. 일반 관리자에게 자동으로 부여하지 않는다. 수퍼관리자는 구매처리가 기본 허용되지만, 개인앱 구매신청은 별도로 허용해야 한다. 일반 작업자·반장·원청·열람 계정은 사용할 수 없다. 권한 회수는 다음 서버 요청부터 적용된다. 구매처리는 이메일·비밀번호 또는 Google로 정식 로그인해야 한다.

기존 로그인 상태에서는 첫 구매처리·구매 권한 변경 전에 다시 로그인이 필요할 수 있다. 화면의 **로그아웃 후 다시 로그인**을 누른다.

## 요청자

개인앱 → 구매신청 → 현장·필요일 → 설명/링크/사진/도면/녹음 → 정리하기 → 규격·수량·단위 확인 → 요청 보내기. 여러 파일을 선택하면 첫 파일만 분석하고 전체 파일을 요청에 첨부한다. 제품 찾기는 현재 설정된 검색 가능 AI를 사용하여 출처 링크가 있는 후보를 제시한다. 누락한 규격을 확정값으로 채우지 않는다. 본인 요청만 보이며 구매처리 버튼은 없다.

## 구매자

ERP → 자재·장비 → 구매요청. 목록에서 요청을 열고 정보 필요·보류·품절 사유나 도착예정일을 선택한다. 메시지는 저장된 사실로 자동 작성되어 요청자의 활동함에 보존된다. 동일 상태 재저장에는 알림을 중복 생성하지 않는다.

판매 사이트에서 구매한 뒤 주문 증빙을 첨부하고 구매처·주문번호·금액·수량을 확인한다. 일부 품목/수량만 주문하면 잔량이 남는다. 외부 사이트 버튼은 구매 실행 자체가 아니며 ERP가 임의로 결제하지 않는다. 요청자료와 주문증빙은 접근권한이 다른 비공개 파일이다.

현장 수령자가 기존 자재입고 원장에서 입고를 확정한 뒤, 구매자는 해당 입고 줄과 수량을 연결한다. 중복 연결·과입고·단위 불일치를 차단한다. 배송완료를 입고확정으로 바꾸지 않는다. 새 구매 원장은 금액을 급여·경비에 자동 재기표하지 않는다.

## 운영

분석은 기존 `ai_task_jobs`와 `document-analysis` 연결의 `purchases` 큐에서 처리된다. 매분 스케줄러가 구매 분석 및 푸시 작업을 처리하며 기존 default 큐는 소비하지 않는다. 파일 저장 완료 후 앱을 닫아도 분석은 남는다. 오래된 대기/실행 상태는 사용자 조회 시 실패로 표시하여 무기한 진행 중으로 남지 않게 한다.

AI 분석·인터넷 후보 검색은 기존 AI 키와 모델 접근권한을 사용한다. 자동시험은 실제 유료 호출을 하지 않는다. 도면의 숨은 부속/불명확한 축척/미지정 치수는 확정 물량으로 삼지 않는다. 후보 가격·재고·배송일은 주문 시 판매사 확인이 필요하다.

주문메일과 쇼핑몰 결제를 실시간으로 감시하는 브라우저 확장이나 새 메일 수집 권한은 이 기능에서 만들지 않는다. 구매 증빙 분석·기록까지 제공하며, 외부 구매는 구매자의 동작이다. 문자 발송은 포함하지 않고 앱 활동함을 확정 기록으로 사용한다. 푸시 허용 기기에는 추가 전송을 시도하며 전송실패가 원장 저장을 취소하지 않는다.
