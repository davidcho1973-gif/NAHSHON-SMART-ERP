# 공정미팅 → ERP 연결

현장 상황실의 **공정미팅**에서 녹음하거나 파일을 선택하고 **업로드하고 분석 시작**을 누릅니다. 서버 저장 완료 후 앱을 닫아도 작업이 계속됩니다. 최대 30분, 64MB이며 녹음 중에는 화면을 유지합니다. 참석자에게 녹음을 알린 뒤 사용합니다.

## 실제 처리 흐름

1. 현장·회의일·참석자 입력 → 브라우저 녹음 또는 파일 선택. 기록한 음성은 업로드 완료까지 해당 브라우저에 임시 보관합니다. 업로드는 1MB 조각을 이어 올리고 원본 SHA-256을 검증합니다.
2. 서버의 private durable storage에 보관 → PostgreSQL 전용 `meeting-analysis` 연결 / `meetings` 큐. 기존 `QUEUE_CONNECTION=sync` 여부와 무관하게 비동기입니다. 기존 default 큐는 소비하지 않습니다.
3. Gemini Transcribe와 ElevenLabs Scribe v2를 병렬 요청합니다. Gemini에는 현장 자재·공정 명칭 사전을 넣고, Scribe에는 화자 구분과 단어 시간을 요청합니다. Gemini는 사전과 화자/단어 시간 조합을 허용하지 않아 역할을 나누었습니다. Scribe 화자 번호는 직원 신원이 아닙니다.
4. Gemini Pro가 두 전사본과 현장에 연결된 BOQ·WBS·조달·제출물·미완료 업무를 대조합니다. 최종 정정, 부정, 조건, 수치·날짜 충돌을 구별하여 원문 인용과 확인 질문을 남깁니다.
5. 명확한 기존 정보 조회 및 담당자가 명시된 조건 없는 내부 요청만 자동 처리합니다. 진척·계획·조달·검사 일정·실제 출역 인원은 사람이 근거를 확인하고 반영합니다. 승인·지급·외부 발송은 해당 업무 화면에서 처리합니다.
6. 신규 장부를 별도로 만들지 않고 기존 상황실 할 일·공정·조달·출역 보고를 이용합니다. 일일 마감은 업로드 날짜가 아닌 회의 날짜로 집계합니다. 자동으로 일일 마감을 확정하거나 이메일로 보내지는 않습니다.
7. 업로더의 ERP 알림센터에 결과/실패를 알립니다. 다음 회의에는 해당 현장의 미완료 업무를 표시합니다. 외부 푸시·메일·Slack 발송은 포함하지 않습니다.

## “방문 언제 입고되는지 확인” 예시

- 등록된 문/PO를 찾고 ERP 납품 예정일·발주 상태를 조회합니다. 기록된 예정일은 공급업체의 최신 확약이나 실제 입고 증거와 구별해 표시합니다.
- 예정일이 없거나 지났으면 내부 납기 확인 업무를 만들고, 동일 대상의 미완료 납기 확인 업무가 있으면 연결합니다.
- 같은 이름의 문·공정 후보가 여럿이면 선택을 요구합니다. BOQ만 찾았으면 발주 완료라고 가정하지 않습니다.
- 질문을 ETA 변경·입고 완료·신규 발주로 바꾸지 않습니다. 공급업체에 직접 연락하거나 회신을 가져오는 메일 연동은 이번 구현 범위가 아닙니다.
- 연결된 WBS의 등록 종료일과 ETA를 비교해 늦음을 표시합니다. 실제 설치 필요일과 동일한지는 현장 공정 연결을 확인해야 합니다. 공정일을 임의로 이동하지 않습니다.

## 확인과 정정

**수정·대상 선택 → 근거 듣기/두 전사 대조 → 확인 후 반영.** 분석 후 원본 대상이 바뀌면 최신 내용을 다시 확인해야 합니다. 실제 발주일이 없는 상태에서 상태를 바꾸려면 발주일도 입력합니다. 분석일을 발주일로 만들지 않습니다. 검사 홀드가 해제되지 않은 완료 진척은 막습니다.

반영 취소는 대상이 그대로일 때 가능합니다. 이미 누군가 수정한 값/처리한 업무, 다른 회의에서도 참조하는 요청, 후속 CPM 일정이 함께 이동한 경우에는 원래 모듈에서 영향 범위를 확인하고 정정합니다. 비어 있던 WBS/조달 값 복원은 원래 모듈에서 처리합니다. 원음·전사와 수정/확인/제외/취소 이력을 보존합니다.

공정 일정 변경은 기존 CPM 계산에 따라 후속 일정에 영향을 줄 수 있습니다. 조달을 입고 완료로 바꾸면 기존 회계 **승인 대기** 연결이 실행될 수 있으며 지급이나 회계 승인을 대신하지 않습니다. 개인별 근태·급여는 회의 출역 보고로 생성하지 않습니다.

## 서버 설정 / 배포

- `GEMINI_API_KEY`: Interactions / Files / 선택한 분석 모델 접근 가능한 유료 키.
- `ELEVENLABS_API_KEY`: Scribe v2 사용 가능한 키. 채팅·저장소에 기입하지 않고 Laravel Cloud의 보안 환경변수에 등록합니다.
- `MEETING_DISK`: private durable disk. 버킷이 있으면 기본 s3를 선택합니다. Cloud의 임시 local 저장소를 영구 보관으로 사용하지 않습니다.
- `MEETING_TRANSCRIBE_MODEL=gemini-3.5-transcribe`, `MEETING_ANALYSIS_MODEL=gemini-3.1-pro-preview` (HIGH reasoning). 실제 제공되는 Pro 모델명으로 고정하고 저성능 모델로 조용히 대체하지 않습니다. Preview 수명과 모델 접근 상태는 운영 점검 대상입니다.
- 스케줄러가 매분 `queue:work meeting-analysis --queue=meetings --stop-when-empty --max-time=50 --tries=2 --timeout=1500`을 중복 없이 기동합니다. 전용 worker를 운영하면 같은 큐/연결로 실행합니다. `retry_after=1800`은 작업 timeout보다 깁니다.
- 자동 재시도 2회, 사용자가 재시도한 총 분석 시도는 최대 5회. 성공한 전사본은 재사용하고 실패한 제공자만 다시 호출합니다. 부분 JSON/전사 실패를 성공으로 반영하지 않습니다.
- `php artisan meetings:health`: 키 존재 여부·모델·큐·31분 이상 정체 건수만 읽습니다. 실제 유료 API 성공이나 품질 검증을 의미하지 않습니다. 비밀값은 출력하지 않습니다.
- 공유 routes/config/SPA 변경은 전용 서버 작업과 기존 상황실 진입 연결을 위해 필요합니다. 마이그레이션은 기존 장부를 삭제하지 않고 회의 근거 테이블과 항목 메타데이터를 추가합니다.

## 확인한 한계

현장과 연결되지 않은 공통/Global 행은 자동 후보에서 제외합니다. 모듈별 1,000개를 넘으면 잘린 후보임을 표시하고 자동 반영을 보류합니다. 문서 본문·이메일의 최신 회신까지 실시간 검색하는 기능은 포함하지 않습니다. 미완료 요청의 일반 문장 중복은 제목·담당·기한이 같은 경우 방지하며, 다른 표현의 의미상 중복은 검토가 필요합니다.

합성 음성/API 응답으로 서비스 계약과 ERP 안전장치를 시험한 것과 실제 한국어·영어 현장 회의의 인식 정확도는 별개입니다. 운영 키 연결 후 실제 회의 샘플로 숫자/제품명/정정/담당자/날짜/조건 인식, 처리 시간, 제공자 청구를 점검해야 합니다. 이번 배포 검증 기록은 WORK_LOG와 별도 릴리스 기록을 참조합니다.
