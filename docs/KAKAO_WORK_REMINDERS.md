# 카카오 출퇴근·일일보고 알림

2026-09-07. 나손 요청: 미국 번호(+1)로 카카오톡 업무 링크를 예약 발송. 현재 발송업체 계정·비즈니스 채널 없음. **코드만 설치하며 실제 발송은 기본 OFF**. 임의의 개인 카톡방에 보내는 기능이 아니라, 수신 번호별 공식 알림톡이다.

## 개통 순서

1. SOLAPI에 나손 사업자(미국 법인)의 가입·채널 개설 자격, 미국 +1 번호로 인증한 카카오톡 수신자에 대한 **알림톡** 지원을 확인한다. 국제 SMS 지원과 구별한다. 현재 공급계약/계정 개통/미국 수신 실기 검증은 하지 않았다. SOLAPI 공개 API는 country=1을 정의하지만 특정 계정의 발송 가능 여부를 증명하지 않는다.
2. 사업자 인증 및 카카오 비즈니스 채널을 준비하고 SOLAPI와 연동한다. API Key/Secret, 채널 pfId를 발급한다. 채팅·소스·PR에 비밀키를 올리지 않는다.
3. 아래 출근·퇴근·일일보고 템플릿 3개를 등록해 카카오 심사를 받는다. **업무 요청도 승인 보장 대상이 아니다.** 반려 시 공급사의 수정 지침에 맞춰 문안을 다시 심사한다. 템플릿마다 변수 이름은 아래와 일치해야 한다. 원하는 경우 `ERP 열기` 웹 링크 버튼에 `#{링크}`를 사용하되 실제 등록 가능한 URL 변수 형식은 업체 검수에서 확인한다. 본문 링크만으로도 연결된다.
4. Laravel Cloud의 **NAHSHON 환경**에 아래 환경변수를 넣는다. 첫 설정은 OFF로 유지하고 재배포한다. 다른 회사나 staging에는 발송을 켜지 않는다.
5. ERP → 설정 → **카카오 업무 알림**에서 직원별 본인 카카오 번호(+1xxxxxxxxxx), 수신 확인, 발송 요일·시간을 등록한다. 현장 시간대는 현장 관리에서 확인한다. 사바나는 `America/New_York`이며 일광절약시간이 적용된다. 직원은 현장과 활성 로그인 계정이 있어야 한다.
6. 직원 1명에 한해 동의를 받고 테스트 시간으로 예약한다. 업체에서 미국 번호 지원을 확인한 뒤 `KAKAO_CONFIRMED_COUNTRIES=1`, 승인받은 템플릿·키·URL을 설정하고 NAHSHON만 `KAKAO_REMINDERS_ENABLED=true`로 재배포한다. 승인된 실제 수신 시험으로 메시지 도착·로그인·링크 연결을 확인한 다음 나머지 직원을 활성화한다. 이 문서 작성 과정에서는 실제 발송을 하지 않았다.

```dotenv
KAKAO_REMINDERS_ENABLED=false
SOLAPI_API_KEY=
SOLAPI_API_SECRET=
SOLAPI_KAKAO_CHANNEL_ID=
KAKAO_APP_URL=https://nahshon-smart-erp-nahshon-mep-hntasf.laravel.cloud
KAKAO_CONFIRMED_COUNTRIES=
KAKAO_TEMPLATE_CLOCK_IN=
KAKAO_TEMPLATE_CLOCK_OUT=
KAKAO_TEMPLATE_DAILY_REPORT=
```

`erp.nahshonmep.com`은 HTTPS와 로그인 연결을 확인한 뒤 `KAKAO_APP_URL` 및 승인 템플릿을 함께 변경한다. URL에는 경로·쿼리·토큰을 넣지 않는다. API 키는 화면에서 조회하지 않는다. 수신 번호는 DB에서 암호화한다.

## 심사용 문안 초안 (승인 전)

출근:
```
[나손 업무 안내]
#{이름}님, #{날짜} #{현장} 출근 기록을 확인해 주세요.
현장에 도착하셨다면 ERP에서 출근을 등록해 주세요.
#{링크}
```
퇴근:
```
[나손 업무 안내]
#{이름}님, #{날짜} #{현장} 퇴근 기록을 확인해 주세요.
오늘 업무를 마치셨다면 ERP에서 퇴근을 등록해 주세요.
#{링크}
```
일일보고:
```
[나손 업무 안내]
#{이름}님, #{날짜} #{현장} 일일보고를 확인해 주세요.
오늘 작업 내용을 ERP에서 작성하고 제출해 주세요.
#{링크}
```

본문·버튼 변수는 `#{이름}`, `#{날짜}`, `#{현장}`, `#{링크}`. 출퇴근 링크는 `/attendance-app`, 보고 링크는 `/attendance-app/ops-room`. 기존 로그인이 필요하며 수신만으로 근태나 보고를 만들지 않는다. 보고 완료 판단은 ERP 정본인 **현장+날짜+공종/부서** 단위다. 개인별 별도 보고 완료로 해석하지 않는다.

## 동작·운영

- `php artisan kakao:remind-work --dry-run`: 현재 시각 대상/제외 건수만 확인, 발송·발송기록 쓰기 없음. OFF에서도 확인 가능하다. 실제 발송 명령은 `--dry-run` 없는 명령이므로 개통 후에만 사용한다.
- scheduler가 10분 간격으로 확인한다. 지정 시각부터 60분 미만인 대상만 처리하며, 하루 직원/알림종류당 1개 DB 고유 키로 중복을 막는다. 최대 20번의 API 호출/실행, 최악 5분. 현재 소규모 현장용이며 같은 시간에 120건을 초과하는 예약은 1시간 내 모두 처리되지 않을 수 있어 대규모 적용 전 배치 발송 설계가 필요하다.
- 수신중지·퇴사·계정 비활성·현장 변경·현장 비활성은 발송 제외. 현장을 옮겼다면 관리자 화면에서 시간대를 확인하고 다시 저장해야 한다. 공휴일/개인휴가 자동 연동은 없으므로 수신 사용을 끈다.
- 출근 기록/세션이 있으면 출근 알림 제외. 당일 출근이 없으면 퇴근·일일보고 알림 제외. 이미 퇴근했거나 같은 공종/부서 보고가 제출됐으면 해당 알림 제외.
- 처리 중 이미 보낸 요청은 수신 중지를 하더라도 회수할 수 없다. 처리 시점 제외 판정도 그날 알림을 소비한다. 휴가/상태를 정정했다고 같은 날 자동 재발송하지 않는다.
- 발송 키를 DB에 먼저 확보한다. 타임아웃·프로세스 중단은 결과 불명으로 보존하고 자동 재시도하지 않는다. 업체 메시지 ID로 SOLAPI 발송 내역에서 최종 도착 여부를 확인한다. `accepted`는 접수이며 도착 완료가 아니다. 현재 별도 상태 조회/웹훅 동기화는 구현하지 않았다.
- SMS 대체발송은 `disableSms=true`로 차단한다. 실제 카카오 발송에는 업체 요금이 발생한다. 이 변경은 웹 푸시 알림을 유지한다.
- 관리자·최고관리자만 수신 설정/내역을 조회·변경할 수 있다. 반장·팀장·일반작업자에게 다른 직원 전화번호나 운영 비밀키를 노출하지 않는다.

## 근거

- [SOLAPI 메시지 발송 API](https://solapi.com/developers/api/messages): 공식 ATA/템플릿·변수, 국가번호 별도 필드, SMS 대체발송 차단, 접수 응답.
- [SOLAPI API 인증](https://solapi.com/developers/api/authentication-api-key): HMAC-SHA256, 시각+salt 서명.
- [SOLAPI 시작 가이드](https://solapi.com/guides/start): 채널·사업자 준비.
- [KT 해외 알림톡 공식 답변](https://communis.kt.co.kr/cs/qna/view.do?cate=qna&qnaIdx=576): 해외번호 인증 카카오톡에 알림톡 가능. KT의 설명이며 SOLAPI 계정 개통 보장은 아님.
- [SOLAPI 상태 코드 설명](https://solapi.com/developers/api/msg-groups-getGroupMessageList): 2000 접수 / 4000 발송 완료.
