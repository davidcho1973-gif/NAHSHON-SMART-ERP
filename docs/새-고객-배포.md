# 새 고객 배포 — 코드 하나, 배포 여럿

고객사마다 앱을 따로 세우되 **코드는 한 벌만 둔다.**

**왜 이 구분이 전부인가** — 코드를 복사하면 처음 석 달은 편하다. 고객이 요구하는 것을
그 고객 코드에서 바로 고치면 되기 때문이다. 1년이 지나면 서로 다른 제품 세 개가 된다.
A사에서 고친 것을 B사에 옮기려는데 코드가 이미 달라 안 붙는다. 한 곳을 고쳐 전부에
반영하는 길이 막히는 순간, 회사가 고객 수만큼 쪼개진다.

그래서 규칙은 하나다.

> **고객 이름도, 고객만의 숫자도, 코드에 넣지 않는다.**
> 새 고객은 환경변수만 채우면 선다.

이 규칙은 `OrgIdentityTest::test_no_customer_name_is_left_in_the_source` 가 지킨다.
소스 어딘가에 고객 이름을 적으면 테스트가 깨진다.

---

## 값이 어디서 오는가

두 곳뿐이다. 순서가 있다.

| | 무엇 | 누가 언제 바꾸나 |
|---|---|---|
| 1 | **`org_settings` 표** | 고객사 최고 관리자가 화면(**조직 설정**)에서 |
| 2 | **`config/org.php`** ← 환경변수 | 우리가 배포할 때 |

표가 비어 있으면 설정 파일이 답한다. **새 배포는 아무것도 저장하지 않은 채로 선다.**

화면에서 값을 지우면 다시 설정 파일 값으로 돌아간다 — 빈 줄로 남기지 않는다.

### 왜 스케줄 시각은 화면에서 못 바꾸나

`routes/console.php` 는 **매분** 평가된다. 거기서 표를 읽으면 `schedule:run` 이 매분
데이터베이스를 깨워, 서버리스 요금이 그대로 늘어난다. 설정 파일은 캐시되므로 그 일이
없다. 그래서 자동 마감 시각은 환경변수로만 바꾼다.

---

## 새 고객 하나 세우기

### 1. Laravel Cloud 에 환경 추가

새 Environment 를 만든다. 데이터베이스도 **그 고객 전용으로 새로 만든다.**

> 다른 고객의 데이터베이스를 복제해서 쓰지 않는다. 복제하면 `org_settings` 에 남은
> 옛 고객 이름이 환경변수를 이긴다 — 화면은 멀쩡하고 고객만 남의 이름을 본다.
> `org:provision` 이 이 경우를 경고한다.

### 2. 환경변수

**반드시 넣는 것**

```
APP_NAME=ERP
APP_KEY=            ← php artisan key:generate --show 로 새로 만든다. 고객마다 달라야 한다.
APP_URL=https://abc.example.com
ORG_NAME=ABC 건설
ORG_CODE=ABC
CACHE_STORE=file
GOOGLE_CLIENT_ID=
GOOGLE_CLIENT_SECRET=
GOOGLE_REDIRECT_URI=https://abc.example.com/auth/google/callback
```

**필요하면 넣는 것** — 안 넣으면 아래 기본값으로 선다.

| 변수 | 기본 | 뜻 |
|---|---|---|
| `ORG_SHORT_NAME` | `ORG_NAME` | 홈 화면 아이콘 밑 이름 (12자 안쪽) |
| `ORG_LEGAL_NAME` | `ORG_NAME` | 계약서 · W-9 에 찍히는 법인명 |
| `ORG_COLOR` | `#0ea5e9` | 버튼 · 강조 색 |
| `ORG_SUPPORT_EMAIL` · `ORG_SUPPORT_PHONE` | 없음 | 작업자가 막혔을 때 연락할 곳 |
| `ORG_EVENING_FINALIZE_AT` | `20:00` | 저녁 자동 마감 |
| `ORG_EVENING_GRACE_MINUTES` | `30` | 아직 현장에 있는 사람은 건너뛰는 여유 |
| `ORG_SAFETY_NET_AT` | `00:05` | 자정 안전망 |
| `ORG_INDIRECT_CUTOFF_HOUR` | `16` | 협력사 자동 퇴근 시각 |
| `ORG_DUPLICATE_WINDOW_MINUTES` | `5` | 중복 스캔으로 보는 간격 |
| `ORG_GEO_EXIT_BUFFER_METERS` | `80` | 현장 이탈 판정 버퍼 |
| `ORG_GEO_DWELL_SECONDS` | `600` | 이탈 확정까지 밖에 있어야 하는 시간 |
| `ORG_GEO_MIN_ACCURACY_METERS` | `75` | 이보다 오차가 크면 위치를 안 쓴다 |
| `ORG_STANDARD_HOURS_PER_WEEK` | `40` | 주 기준 근무시간 |
| `ORG_PAY_PERIOD_DAYS` | `14` | 급여 주기 |
| `ORG_DOCS_ALERT_AT` | `07:00` | 만료 임박 서류 알림 |
| `ORG_OPS_DIGEST_AT` | `18:00` | 상황실 하루 요약 |
| `ORG_ACCRUAL_AT` | `05:30` | 임대료 · 월세 자동 계상 |

> **세율은 여기 없다.** FICA · Medicare 는 회사 정책이 아니라 연방법이다. 고객이
> 고칠 수 있게 두면 잘못 고쳤을 때 세금 신고가 틀어진다.

### 3. 도메인 · 구글 로그인

`docs/도메인-전환.md` 와 같은 절차다. 고객마다 한 번씩 한다.

- Laravel Cloud → Domains 에 주소 추가 → 나오는 값을 DNS 에 CNAME 으로
- 구글 콘솔 → 승인된 리디렉션 URI 에 `https://<주소>/auth/google/callback` 추가

### 4. 배포하고 세우기

```bash
php artisan migrate --force
php artisan org:provision --admin=사장님이메일@고객사.com
```

`org:provision` 이 하는 일 — 자사 회사 한 줄을 만들고, 최고 관리자를 세우고,
설정이 기본값인지 확인한다. **여러 번 돌려도 안전하다.** 무엇을 할지 먼저 보려면
`--dry-run` 을 붙인다.

### 5. 확인

```
https://<주소>/build-version
```

```json
"org": {
  "name": "ABC 건설",      ← 고객 이름이 나와야 한다
  "configured": true,      ← false 면 ORG_NAME 이 안 들어갔다
  "customized_keys": []
},
"domain": { "matches": true },
"scheduler": { "running": true },
"cache": { "store": "file" }
```

`configured` 가 **false** 면 이 배포는 기본값 그대로 서 있다. 화면은 멀쩡해 보이고,
**고객 눈에만 남의 회사 이름이 보인다.**

`customized_keys` 에 값이 있는데 새 배포라면, 다른 고객의 데이터베이스를 복제해
왔다는 뜻이다. 그 값이 환경변수를 이긴다.

마지막으로 **로그인을 한 번 해 본다.** 구글 리디렉션이 맞는지 확인하는 유일한 방법이다.

## 시험 데이터 비우기

시험하며 쌓인 것을 비우고 다시 해 볼 때. **기본은 미리보기라** 그냥 치면 아무것도
지워지지 않고 무엇이 지워질지만 보여 준다.

```bash
php artisan erp:reset --only=attendance      # 출퇴근 기록만 (직원·현장은 그대로)
php artisan erp:reset                        # 업무 데이터 (현장·회사·관리자는 그대로)
php artisan erp:reset --all                  # 전부 (현장부터 다시 만들어야 한다)
```

실제로 지우려면 뒤에 `--force` 를 붙인다. 운영 환경에서는 거부한다.

`--only=attendance` 는 출퇴근 기록과 거기서 계산된 것들(근무시간·GPS 재실 상태)까지
같이 비운다. 근무시간을 남겨 두면 기록은 없는데 급여에는 시간이 잡혀 있는 상태가
되고, 화면상으로는 멀쩡해 보인다.

올려 둔 파일(배지 사진·문서)은 저장소에 남는다. 표에서만 사라진다.

## 고객이 스스로 바꾸는 것

**조직 설정** 화면(최고 관리자만). 여기 있어야 회사 이름 하나 바꾸는 데 우리한테
연락이 오지 않는다. 고객이 열 곳이면 그 연락도 열 배가 된다.

회사 이름 · 짧은 이름 · 법인명 · 대표 색 · 문의 이메일 · 문의 전화.

바꾸면 화면·앱 이름·이메일·인쇄물이 전부 따라간다. 다만 **서버가 그리는 자리(제목,
사이드바)는 새로고침해야 바뀐다.**

---

## 고칠 때의 규칙

새 고객이 "우리는 이게 달라요" 라고 할 때, 갈림길이 여기다.

| 하지 말 것 | 대신 |
|---|---|
| 그 고객 배포에서만 코드를 고친다 | **한 벌뿐이다. 그런 배포는 없다** |
| `if ($company === 'ABC건설')` 를 넣는다 | 설정 항목으로 만든다 |
| 화면 문구에 고객 이름을 적는다 | `Org::name()` 을 쓴다 |
| 설정 항목마다 마이그레이션을 쓴다 | `Org::EDITABLE` 에 한 줄 추가 |

`if (고객 이름)` 이 한 줄이라도 생기는 순간 코드가 갈라지기 시작한다. 예외가 정말
필요하면 반드시 **설정값**으로 만든다 — 그러면 다음 고객이 같은 요구를 했을 때
코드를 또 고치지 않는다.

## 나중에 플랫폼(멀티테넌트)으로 갈 때

지금 구조는 **배포 하나에 고객 하나**다. 고객이 5~10곳을 넘어 배포가 귀찮아지면
그때 한 배포에 여러 고객을 담는 구조를 검토한다.

지금 해 둔 일이 그때 그대로 쓰인다 — 고객마다 다른 값이 이미 `Org` 한 곳에 모여
있으므로, "이 값을 고객별로" 로 바꾸면 된다. 값이 코드에 흩어져 있었다면 100개
테이블을 전부 뒤져야 했을 일이다.

**지금 서두를 이유는 없다.** 팔리는지 모르는 채로 몇 달을 쓰는 것이 가장 비싸다.
